# AQPrompts

AQPrompts is a Next.js application for browsing AI image prompts, newsletter delivery, prompt engagement tracking, and Paddle billing.

## Environment setup

Copy `.env.example` to `.env.local` and replace every placeholder needed by the features you deploy. Never commit `.env`, `.env.local`, provider downloads, database URLs, access tokens, webhook secrets, or private deployment logs.

Variables prefixed with `NEXT_PUBLIC_` are embedded in browser JavaScript. This project limits that namespace to public analytics and site-verification IDs, public URLs, Paddle client-side tokens, Paddle price IDs, and the Paddle environment. Server credentials—including `RESEND_API_KEY`, `AUTH_SECRET`, `CRON_SECRET`, KV tokens, `DATABASE_URL`, `PADDLE_API_KEY`, and `PADDLE_WEBHOOK_SIGNING_SECRET`—must never receive a public prefix.

For production billing configuration, API-key permissions, notification events, and pre-launch tests, follow [docs/paddle-go-live-checklist.md](docs/paddle-go-live-checklist.md).

The Promptshe Google Apps Script uses Script Properties as its server-side secret store. Configure `WHATSAPP_LINK`, `PAYMENT_LINK`, and `PROMPTSHE_SHARED_SECRET` in Apps Script Project Settings rather than placing those values in `Code.gs`. Set the same random value in the app's server-only `PROMPTSHE_TRIAL_SHARED_SECRET` variable.

MCP prompt publishing and photo-upload capabilities are separate from general MCP user authorization and default to disabled. A Super Admin can set individual flags for an authorized OAuth subject through `POST /admin/api/mcp/authorizations` using `action: "set_capabilities"`, the registered `clientId`, and a `capabilities` object containing any of `publish`, `uploadImages`, or `publishBlog`. The `upload_photo_image` tool accepts base64-encoded JPEG, PNG, or WebP image data up to 3 MB and uploads it to the existing Cloudinary media library. Blog drafts are private to their MCP owner or an explicit assignment; authorized users may create drafts and read published posts, but existing drafts require ownership or explicit assignment. Blog publishing needs the separate `can_publish_blog` flag. A Super Admin can assign or revoke draft access using `POST /admin/api/mcp/draft-access` with `library: "blog"` and the blog post ID. Existing blog drafts receive no automatic access. MCP blog article content is accepted as plain text and HTML-escaped for safe rendering. Apply `scripts/add-mcp-oauth-authorization.mjs` through the approved database migration process before deploying these capabilities. MCP does not expose prompt or blog deletion.

MCP OAuth uses `https://www.aqprompts.com/api/mcp` as its protected resource. In Descope mode, Claude dynamically registers a public client at AQ's `/oauth/register` endpoint, then authenticates with AQ's first-party `/authorize` and `/oauth/token` endpoints. The registration endpoint accepts only Claude's exact callback URI, authorization-code and optional refresh-token grants, code response, and public-client token authentication; each issued client ID and its refresh-grant capability are persisted in `mcp_oauth_clients`. AQ exchanges the authorization code with Descope using the server-only `AQ_MCP_DESCOPE_CLIENT_ID` and `AQ_MCP_DESCOPE_CLIENT_SECRET`, verifies the Descope ID token signature, issuer, expiry, subject, and app audience, then issues short-lived opaque MCP access tokens and, only when registered, rotating refresh tokens. Access and refresh token hashes—not raw token values—are stored and bound to the registered Claude client ID and canonical resource. Refresh tokens are single-use and expire after 30 days. MCP requests resolve the access token and still require a separate admin-granted subject/client authorization; registration and Descope login do not grant MCP permissions. Super Admins select the registered OAuth client when granting or revoking MCP authorization. The Super Admin MCP access panel can identify unlinked verified OAuth subjects seen in the last 24 hours; it returns only the subject, registered client, and sign-in time, never token values. Configure `AQ_MCP_OAUTH_ISSUER`, `AQ_MCP_OAUTH_DISCOVERY_URL`, `AQ_MCP_OAUTH_JWKS_URL`, `AQ_MCP_OAUTH_SIGNING_ALGORITHM`, `AQ_MCP_DESCOPE_CLIENT_ID`, `AQ_MCP_DESCOPE_CLIENT_SECRET`, and `AQ_MCP_RESOURCE_URI` only after verifying the Descope tenant. Apply `scripts/add-mcp-oauth-authorization.mjs` through the approved database migration process before enabling this flow; it creates the client registry and hashed token stores additively without changing existing content. The secret must remain server-only. Preview diagnostic behavior is not enabled in Production. Do not copy Preview OAuth values into Production without verifying the Production tenant; Production OAuth changes and deployment require explicit approval.

## Connect Claude to AQPrompts with MCP

The MCP server lives at `https://www.aqprompts.com/api/mcp` (protected resource `https://www.aqprompts.com/api/mcp`). It exposes 12 tools: `list_prompts`, `get_prompt`, `list_categories`, `create_draft`, `update_draft`, `publish_prompt`, `upload_photo_image`, `list_blog_posts`, `get_blog_post`, `create_blog_draft`, `update_blog_draft`, and `publish_blog_post` (see `public/.well-known/mcp/server-card.json` for the full list and input schemas). MCP does not expose prompt or blog deletion.

1. **Dynamic client registration (DCR).** Claude registers a public client by POSTing to `/oauth/register` (only `https://claude.ai/api/mcp/auth_callback` is accepted as the redirect URI). The issued client ID is stored in `mcp_oauth_clients`.
2. **Authorize.** Claude opens `/authorize` with `response_type=code`, PKCE `S256`, and the canonical `resource`. AQ redirects to Descope for sign-in, then back to Claude with an authorization code.
3. **Token exchange.** Claude POSTs the code to `/oauth/token` and receives a short-lived opaque access token (1 hour) and, only for clients registered with the refresh grant, a rotating refresh token (30 days, single-use). Token responses include `scope: "openid profile email"`. Revoke a token at any time with `POST /oauth/revoke` (RFC 7009).
4. **Admin grant.** A Super Admin links the verified OAuth subject (`sub`) to an existing Admin or Super Admin account in the admin MCP access panel (`/admin/users`), then sets the optional `publish`, `uploadImages`, and `publishBlog` capability flags. Without a grant, MCP calls return 403. A Super Admin can also assign individual drafts to a subject (`POST /admin/api/mcp/draft-access`); unassigned drafts stay hidden.
5. **Call tools.** With an access token and a grant, Claude calls the tools at `/api/mcp`. `upload_photo_image` accepts base64 JPEG/PNG/WebP up to 3 MB and stores it in Cloudinary with the AQPrompts watermark applied. Publish tools require their capability flag.

Descope is the only supported OAuth provider (`AQ_MCP_OAUTH_PROVIDER=descope`). There is no Supabase or password login path for MCP. Server metadata is served at `/.well-known/oauth-protected-resource/api/mcp` and `/.well-known/oauth-authorization-server`.

The Photo prompt admin editor reuses existing `intro`, `customization_tips`, `faqs`, `meta_description`, and per-image `image_alt_texts` fields rather than duplicating them. Prompt detail content that had no existing field is stored in the additive `variations`, `recommended_tool`, `tool_note`, `how_to_use`, and `tools` columns. The saved tips, variations, recommended tool, usage steps, compatible-tool badges, and FAQs are displayed on the public Photo prompt detail page; `meta_description` feeds search metadata. New columns are introduced by `scripts/add-prompt-detail-fields.mjs`; apply it only through the approved database migration process before deploying the code.

Public prompt directory, sitemap, and Text library reads use precomputed eligibility flags. Apply `add-public-prompt-eligibility.mjs` with the guarded migration runner, deploy the writer changes, then run `backfill-public-prompt-eligibility.mjs` with the same explicit target/environment before deploying the optimized readers. The backfill compares the existing JavaScript policies across all prompt rows and refuses to write on any mismatch. Run `npm run db:verify:public-prompt-eligibility -- --env-file=<explicit-env-file> --target=<development|preview|production>` before reader rollout to compare sitemap rows, directory JSON, and Text library results against the legacy behavior. Keep each database operation on the approved migration target; generic `.env` and `.env.local` files are not accepted by the guarded runner.

## Secret rotation warning

If any credential or private access URL was ever hardcoded or committed, removing it from the current files does not remove it from Git history, forks, build logs, or deployment caches. Rotate every previously exposed value immediately, including API keys, database/KV credentials, webhook and cron secrets, OIDC tokens, and private invite URLs. Revoke the old values before deploying and purge Git history separately if the repository was shared.
